# 모드 A 템플릿 패치 — 확률 블록만 교체

> **원본 `모드A_프리뷰_템플릿_축구.md`를 통째로 갈아엎지 않는다.**
> 섹션 구성·문체·SEO 규칙은 이미 잘 돌아가고 있고, 틀리는 원인은 확률 블록에 있다.
> 이 문서의 내용만 원본 템플릿에 이식한다.

## 패치 1 — `6. 호랑이의 최종 예측` 머리 2줄

**기존 (1줄)**
```
**예상확률(내/시장):** 홈승 xx%(xx) / 무 xx%(xx) / 원정승 xx%(xx) | AH(라인) 커버 xx%(xx) | U/O(라인) 언더 xx%(xx)
```

**교체 (2줄)**
```
**예상확률(내/시장):** 홈승 xx%(xx) / 무 xx%(xx) / 원정승 xx%(xx) | AH(라인) 커버 xx%(xx)[푸시 x%] | U/O(라인) 언더 xx%(xx)
**정보 등급:** X · 시장가중치 w=0.xx · 최대 이탈 x%p · 티어 상한 [주력 가능 / 부주력까지 / PASS]
```

정보 등급 줄이 핵심이다. 같은 55%라도 등급 A의 55%와 등급 C의 55%는 전혀 다른 물건이고,
독자에게 그 차이를 알려주지 않으면 글이 틀렸을 때 신뢰가 통째로 무너진다.

푸시 확률은 정푼 AH 라인에서 2% 이상이면 대괄호로 붙인다.
축구 정푼 라인은 대부분 2%를 넘으므로 사실상 상시 표기된다.

## 패치 2 — `4. 흐름 시뮬레이션` 서술 방식

**기존:** 시나리오 A/B/C를 만들고 각각에 확률을 배분한다(합 100%).

**교체:** 시나리오는 **이미 계산된 확률을 설명**한다. 확률을 새로 배분하지 않는다.

작성 순서는 이렇다.

1. `poisson.py`의 스코어 상위 6개를 먼저 본다
2. 그 분포를 세 덩어리로 묶는다 — 정배 / 이변 / 혼돈(무승부·저득점)
3. 각 덩어리의 확률은 **1X2 계산값에서 그대로 가져온다**
4. 각 시나리오에 "몇 분에 첫 골이 나오는가"를 넣는다

```
**A) 정배 — xx%**   (= 홈승 확률)
   유력 스코어: 2-1, 2-0. 선제골 예상 구간 20~35분.
   ...

**B) 이변 — xx%**   (= 원정승 확률)
   유력 스코어: 1-2, 0-1. 선제골 예상 구간 ...

**C) 혼돈 — xx%**   (= 무승부 확률)
   유력 스코어: 1-1, 0-0. ...
```

세 값의 합은 자동으로 100%가 된다. 손으로 맞출 필요가 없고, 맞추려고 조정하면 안 된다.

## 패치 3 — `5. 시장의 냄새` 에 반대 근거 흔적 남기기

이 섹션 말미에 아래 형태의 문단을 하나 추가한다.

```
반대편 논리도 짚어둔다. [반대 픽]을 지지하는 가장 강한 근거는 [근거1]과 [근거2]다.
[근거1]은 [반박]으로 상쇄되고, [근거2]는 [잔존 리스크로 인정]한다.
이 두 번째 지점이 이번 판단의 가장 약한 고리다.
```

확증편향을 막는 장치이면서 동시에 글의 신뢰도를 올린다.
반대 근거를 스스로 적어보고도 결론이 유지되지 않으면 티어를 내리거나 PASS한다.

## 패치 4 — `7. 참고사항` 확장

기존 항목(소스 대비 변경점, 확인 불가 항목, 기록 기준 시각)에 아래를 추가한다.

```
**조회 기준 시각:** YYYY-MM-DD HH:MM KST
**정보 등급:** X — 판정 근거: [라인업 상태 / xG 표본 / 로테이션 변수]
**사용 배당판:** [출처] · 오버라운드 xxx.x% · 마진 x.xx%
**출처:**
- 순위·전적: [출처] (조회 HH:MM)
- xG: Understat 또는 FBref (조회 HH:MM)
- 부상·라인업: [출처] (조회 HH:MM)
- 배당: [출처] (조회 HH:MM)
**확인 불가:** [항목] — 사유
**소스 대비 변경점:** [있으면 항목과 사유, 없으면 "없음"]
```

## 패치 5 — 발행 직후 기록

본문 저장 후 `logs/picks.csv`에 한 줄 append한다. **PASS도 기록한다.**

```
date_kst,league,home,away,market,selection,line,p_model,p_market,p_final,edge_pp,odds_taken,stake_units,closing_odds,tier,result,notes
```

- `tier`: `주력` / `부주력` / `PASS`
- `p_final`: 블렌딩 이후 확률 (이 값이 캘리브레이션 대상이다)
- `closing_odds`: 킥오프 직전에 다시 채운다. **이 열이 비면 CLV를 못 재고, 표본 30건 이하에서는 아무것도 판단할 수 없게 된다.**
- `result`: 모드 B 리뷰 작성 시 `WIN / LOSE / PUSH / HALF_WIN / HALF_LOSE` 중 하나로 채운다

## 패치 6 — 제목 규칙 보강

기존 규칙(분석·예측·승부·배당 금지, 앞 15자에 키워드) 유지하되, 아래를 추가한다.

- **단정형 제목을 쓰지 않는다.** "○○ 완승 예상" 같은 제목은 확률 글의 본문과 모순된다.
- 정보형으로 간다: `[팀A vs 팀B] 선발 라인업·중계 시간 정리`, `[팀A vs 팀B] 부상자 명단과 맞대결 전적`
- 이렇게 하면 SEO 확정 수요 키워드와도 맞고, 결과가 어긋나도 제목이 틀린 글이 되지 않는다.
